# 播放体验修复计划

基线：df3e9791，新分支 feat/playback-version-queue-catalog。

## 已定位
- 自动取流成功立即调用 toggleWriteback，新增替代曲并删除收藏原曲，混淆收藏身份与实际音源。
- 手动换版本也删除原条目；既无明确固定标记，也不保留原条目身份。
- 我的列表的播放操作忽略多选；在线列表把多选加入默认列表后沿默认列表播放，重复曲原位置和既有歌曲打乱后续顺序。
- 预加载直接调用 getMusicUrl，绕过播放器手动偏好处理。

## 分阶段实现与检查
1. 原条目 ID 不变，meta.toggleMusicInfo + manualVersionPinned 表示用户选择；实际取流源只在播放器状态。选定版本失败允许当次救急并明确显示，下次仍先尝试选定版。测试缓存、预加载、迟到响应、喜欢/会话身份。
2. 多选通过既有 tempPlayList 队列按可见列表顺序播放；测试旧队列清空、下一首、重复/已收藏歌曲与各列表入口。
3. 进度条旁队列入口复用既有队列、当前列表与 getNextPlayMusicInfo，区分确定下一首和随机模式未确定部分。
4. 艺人/专辑详情复用 SDK 分页接口；缺 ID、不支持、失败、部分加载不得标成完整歌曲。测试分页与重复/过期响应。

每阶段本地提交与备份；未获正规登录权限前不推送。轻量单 worker 测试，Node 堆上限 512MB，不执行依赖递归 prepare。

## 实现检查点
- 收藏原条目与 `manualVersionPinned`/`toggleMusicInfo` 持久偏好分开，取流实际身份仅 `resolvedMusicInfo`，临时提示单独保留，不被普通状态文字覆盖。
- 缓存仅以实际取流曲目 ID 保存；首选请求不接受跨曲目旧缓存。共享取流入口覆盖预加载；取消请求不发起救急。
- 多选按当前可见列表顺序（不是点击先后）进入原有待播队列，清除旧待播/随机历史，批量结束停止。我的列表、在线列表、下载列表均覆盖。手动重选版本不清除待播队列。
- 所有播放条样式和歌词详情页均有队列入口；随机模式仅承诺已确定下一曲，后续未决明确说明。
- 正序当前项已移除时不再跳过剩余第一首；队列视图复用相同过滤器与下一曲接口。

## 验证边界
- 全量 Vitest 使用单 worker / 512MB。首次完成 863 项，后续新增版本重播/喜欢/批量终点等测试，最终数量见随包日志。
- 原 ESLint 默认全仓 TypeScript 项目在 512MB OOM；缩小 TS include 后保留全部原规则，播放核心、hook 和 Vue 受影响文件通过。
- focused tsc 的受影响播放文件无诊断；整个依赖图仍缺 Electron、electron-log/updater、music-metadata 等验证环境依赖（23条传递诊断），不能标成完整typecheck通过。
- 尚未完成真实 Electron 打包、真实平台目录联网、真实音频听感/UI交互检查；这些与 mocked SDK 单测区分。
